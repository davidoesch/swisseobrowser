Not for operational use

This is an experimental beta prototype. It is not intended for operational use: values, renderings and statistics are computed in the browser, are not validated and may be wrong or incomplete. For authoritative data use the swisstopo products and services directly.

Layer verification: we will check every layer in depth: data access, scaling and no-data, formula, masks and rendering, compared with reference implementations (e.g. GDAL / rasterio reads and the original scripts). Every layer that has not yet passed this check carries the label BETA behind its name: it still needs to be verified, and its values may be wrong. Verified layers carry no label. The status is kept as a checklist in the README and applied to the website on every deployment.

Please note that AI (Claude Code with the Opus 5.5 model, medium effort) was used extensively to prepare this website, adapting it from the Copernicus Browser. The indices were edited and tested manually in QGIS or with rasterio and GDAL.

How this works

Everything on screen comes from public swisstopo services, and the Nutzungsflächen mask from geodienste.ch. There is no other backend.

Basemaps: the layer button at the top right of the map (as in the Copernicus Browser) switches between Map, SWISSIMAGE, Map Grey (wmts.geo.admin.ch: pixelkarte-farbe, swissimage, pixelkarte-grau, from the native LV95 tile grid, also beyond the border) and None.

Map overlay: Labels are the place, road, peak and lake names of swisstopo's base map vector tiles (vectortiles.geo.admin.ch, ch.swisstopo.base.vt) in the style of swisstopo's imagery base map, drawn as text above the data layers. The tiles are in Web Mercator and are moved into the LV95 grid in the browser. The basic image download can include them; the high-res print and the timelapse, which are drawn away from the map, are without labels.

3D terrain: the 3D button drapes the map over swissALTIRegio, swisstopo's 10 m height model (one COG on data.geo.admin.ch), turned into terrain in the browser. Tilt and turn the map with the right mouse button or Ctrl + drag; the compass resets it; 2D returns to the flat map. In 3D the compare list uses the opacity effect, and three more tools appear: 3D settings (gear: the height model, swissALTIRegio or the swissSURFACE3D surface model at 10 m on the swissEO bucket; sky; sun shading and its parameters; vertical terrain scaling), Sun shading (light bulb: a hillshade lit from the sun at the map centre) and Sun time (sun: date and time of that sun). Shadows cast by mountains, a lens flare and anaglyph stereo of the Copernicus Browser are not available in MapLibre.

Map layout: at the top left the date and acquisitions on the map, the Copy link (chain) and Pixel inspector ((i) with a pointer) buttons; at the top right the place search, the layer button and the help (i), below it the area of interest and the tools (with 3D); at the bottom right the zoom buttons, the mouse position (LV95 easting and northing) and the scale bar; the attribution at the bottom left. The chevron in the menu header collapses the menu, the round button at the top left of the map opens it again (on small screens the menu starts collapsed).

Place search: the location search of map.geo.admin.ch (api3.geo.admin.ch SearchServer, type=locations): municipalities, districts, cantons, place names and addresses. Choosing a result zooms to its extent or to its point and drops a pin there.

WMS / WMTS: the third button of the configuration card (next to Compare) opens layers of other map services, as in the Copernicus Browser. The swisstopo WMS (wms.geo.admin.ch) is preset; the pull-down lists the external providers of map.geo.admin.ch (loaded when the panel is opened) and can be searched, and + adds any other WMS or WMTS URL (the service must allow cross-origin requests, CORS). The layers can be searched and paged; a click shows a layer on the map and a second click hides it (the panel opens without an active layer), Add to Compare puts it into the compare list, the chevron shows its legend and description, and Metadata opens its metadata. Layers are drawn from LV95 when the service offers it, otherwise from LV03, Web Mercator, UTM 32N or WGS84, placed on the LV95 grid. Services without CORS headers cannot be shown: the map is drawn with WebGL, which needs them. The services you add are remembered in this browser; the open service and layer, and the external layers in the compare list, are part of the link.

Dates: without a date in the link the latest date with data opens. The calendar and ‹ › only offer days whose acquisitions reach the map view: the data footprint of each relative orbit is read once from the coarsest B04 overview (the STAC geometry is only the rectangular extent). The calendar and the ‹ › buttons query the STAC API data.geo.admin.ch/api/stac/v0.9. Cloud cover is CLOUDPERCENTAGE from each mosaic's metadata.json (OmniCloudMask). When several orbits were acquired on the same day, all of them are mosaicked, most recent on top.

True color (TCI): the JPEG tiles are decoded by the browser itself and kept in a cache, so each COG tile is decoded once; the map uses 512 px tiles like the COGs. The TCI's internal mask decides what is data, so black pixels stay black. On days with more than one scene (orbit), dark strips along a swath edge (mean RGB below 40 within 2 km of the scene edge) always count as no data, as in the swissEO cloud-free mosaics, so the other scene of the day fills them.

Spectral layers: the band COGs are read straight from data.geo.admin.ch over HTTP range requests (geotiff.js). Only the overview matching the zoom and the tiles in view are fetched.

Masks: Clouds hides cloud-mask codes 1 and 2, Cloud shadows code 3, and Terrain shadow terrain-mask value 200 (cast or self-shadow from swissSURFACE3D at acquisition time). The vegetation mask keeps forest or all vegetation of the habitat maps that the swissEO VHI processor uses (COGs in s3-topo-satromo-prod, inside = value ≠ 0): one of the three maps, named by the period in which swissEO VHI uses it, or by default the Habitat Map as used in swissEO VHI100, the one of the date (v1-0 before 2024-07-12, v1-1 before 2025-12-11, v1-2 since). Or the swissTLM3D forest (WMS ch.swisstopo.swisstlm3d-wald, any of Wald, Wald offen, Gebüschwald); broadleaf or conifer forest of the Waldmischungsgrad LFI (BAFU / WSL, share of broadleaf trees above or at most a threshold, 76 % by default); or Nutzungsflächen main categories (geodienste.ch WMS lwb_nutzungsflaechen_v3_0_0, read at 20 m by the legend colours; the coverage depends on the canton). The two-date layers use the mask of the selected date on both dates.

VHI: wms.geo.admin.ch layers ch.swisstopo.swisseo_vhi_v100 and …_vegetation with the item= day selector. Titles and abstracts come from the WMS GetCapabilities document.

Area of interest: the pentagon button on the map draws a rectangle (axis-aligned in LV95) or polygon, or imports KML/KMZ, GPX, WKT, GeoJSON, zipped Shapefiles (from a file or a URL), an MGRS/GEOREF cell or a bounding box (WGS84, LV95, LV03). Limits: files up to 50 MB, areas up to 100,000 vertices. An area imported from a file is only part of a copied link when it is small (about 270 vertices); one loaded from a URL is shared as the URL. Vertices stay editable; drawing again adds a polygon. Statistical info reads the COGs over the area for the selected date (statistics, histogram) and over a date range (time series, CSV); swissEO VHI statistics come from the forest-10m / vegetation-10m COGs. The spectral explorer plots mean reflectance of all 12 bands. The image download can be clipped to the area.

Configurations: as the themes of the Copernicus Browser, a configuration lists the layers for a task: Default, Agriculture, Drought, Drought 2026 with highlights, and Forest. Each layer keeps its own data source and dates.

VHI season sums (Forest): per pixel, over the daily swissEO VHI forest maps from 1 April to the selected day (at most 31 October): the cumulative deficit Σ max(0, 40 − VHI) and the days with VHI below 10, as in the Waldtrockenheit dashboard (which shows them per warning region). Only days with a VHI value count. They are computed in the browser from the daily COGs, so the first view of a season takes a while.

Forest Disturbance Classification: the Sentinel Hub custom script of Joanneum Research (EvoLand), run in the browser on swissEO S2-SR: the model expects Sentinel Hub DN as 10000 × reflectance, which is swissEO DN − 1000. Its 150 trees are loaded on first use from jsDelivr, pinned to a commit.

Coordinates: positions are given in LV95 (EPSG:2056) everywhere, also in the permalink (center=2703331.08,1133878.99, as on map.geo.admin.ch).

Custom mask: the fifth mask of every layer keeps the data inside (or, inverted, outside) your own polygons (e.g. a forest map), loaded from a file or URL like an area of interest (up to 50 MB and 1,000,000 vertices). It applies to the map, statistics, exports and the timelapse.

Highlights: click a story to open it on the map (the card turns blue; a split comparison of two dates, drag the handle); the chevron shows the text, whose last line opens the compare settings. Texts after watson.ch (10 August 2026) and SRF Meteo (9 July 2026), credited in each story.

NDDI: by default with the NIR/SWIR NDWI of Gu et al. (2007). The green/NIR NDWI of the openEO notebook is selectable, but saturates (99.8 % of the pixels at ±1 in a test, with or without the reflectance offset).

Loading: the box at the bottom left counts the tiles still rendering and the requests in flight, and flags a slow connection after 6 s.

NDVIdiff / NDVIz: monthly products for the end of July, August and September (forest perimeter); the product nearest to the selected date is shown, also in compare (each entry gives the date of its product), timelapse and export. NDVIdiff v200 BETA (beta data, example COGs on cms.geo.admin.ch, not in STAC): the NDVI change of two-month first-quartile cloud-free mosaics (June/July, July/August, August/September) against the same window one year earlier.

Two-date layers: NDDI change and the NDVI difference to a reference date compare the selected date with a reference: the acquisitions within ±20 days of the same day one year earlier (or of a chosen date), clearest first, per pixel the first clear one (on the map and in the statistics). For a large area of interest the change report is first computed on a coarser grid (up to 320 cells across, from the COG overviews); Compute at 10 m processes the area at full resolution in chunks of 1024 × 1024 cells.

Compare: each entry shows the date of the data it actually shows: the nearest NDVIdiff, NDVIz or NDVIdiff v200 BETA product, the VHI day (the nearest one if the chosen day has none) or the S2-SR date.

Permalink: the address bar is rewritten on every change (view, date, cloud filter, layer, legend range, masks, effects, compare list including WMS / WMTS layers, the open WMS / WMTS service and layer, area of interest, 3D view), so copying the URL reproduces the view.

Projection: EPSG:2056 (CH1903+ / LV95), the native CRS of the basemaps and the COGs, so nothing is reprojected. The map is drawn by MapLibre GL JS with a custom projection for EPSG:2056 and its own tile grid (10 m per pixel at zoom 8), into which the page draws the swisstopo tiles and the swissEO layers.

  • swisstopo/topo-swisseobrowser: this website

  • MapLibre GL JS (custom projection EPSG:2056), proj4js: map
  • geotiff.js: reading the COGs
  • togeojson, shpjs, mgrs, JSZip, gifenc: import, export, timelapse

Import area of interest

Upload a KML/KMZ, GPX, WKT, GeoJSON/JSON file or a zipped Shapefile (.zip with .shp and .prj). Coordinates in WGS84, LV95 (EPSG:2056) or LV03 (EPSG:21781) are detected automatically.
An area imported from a file is not shared when you copy the link: only small areas (up to about 270 vertices) fit into a link. To share an imported area, load it from a URL.
Load a KML / KMZ, GPX, GeoJSON / JSON, WKT file or a zipped Shapefile from the web (also API or WFS URLs that return GeoJSON). The type is taken from the file extension, otherwise from the content. The server must allow cross-origin requests (CORS), e.g. raw.githubusercontent.com, data.geo.admin.ch or most open-data portals; links to web pages or cloud-drive previews do not work. An area or mask loaded from a URL is included in copied links (as the URL).
Paste a WKT polygon, GeoJSON, or a bounding box [minE, minN, maxE, maxN] in LV95. LV03 and WGS84 coordinates are accepted too.
