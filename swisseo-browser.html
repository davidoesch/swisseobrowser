How this works

Everything on screen comes from public swisstopo services — there is no other backend.

Basemaps
wmts.geo.admin.ch — ch.swisstopo.pixelkarte-farbe, ch.swisstopo.swissimage, ch.swisstopo.pixelkarte-grau, on the native LV95 tile grid.

Reference overlay
wmts.asit-asso.ch — asitvd.fond_pourortho, published on the identical LV95 grid (same top-left corner and resolution ladder), so it aligns pixel for pixel with no reprojection. Roads, boundaries and place names on a transparent ground, covering the whole of Switzerland. It sits in its own map pane above the tile pane, so it always paints on top of the data layer rather than under it.

PNG export
Composites the tiles Leaflet currently holds into a canvas at the exact on-screen size, so the export matches the view. All tile services send Access-Control-Allow-Origin: * and the layers request tiles with crossOrigin, which is what keeps the canvas exportable. The scene footprint outline is an SVG overlay and is not included in the export.

Scene search
data.geo.admin.ch/api/stac/v0.9, collection ch.swisstopo.swisseo_s2-sr_v200.

Spectral layers
The band COGs are read straight from data.geo.admin.ch in the browser over HTTP range requests (geotiff.js). Only the overview level matching the current zoom and the tiles covering the viewport are fetched.

Reflectance scaling
B01–B12 and AOT are stored scaled. Every composite and index below applies ρ = DN × 0.0001 − 0.1 before use. DN = 0 is treated as no-data.

VHI
wms.geo.admin.ch — ch.swisstopo.swisseo_vhi_v100 with the item= day selector.

Projection
The map is in EPSG:2056 (CH1903+ / LV95) — the native CRS of both the swisstopo tile grid and the swissEO COGs — so nothing is reprojected.
