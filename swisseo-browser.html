How this works

Everything on screen comes from public swisstopo services. There is no other backend.

Basemaps: wmts.geo.admin.ch (pixelkarte-farbe, swissimage, pixelkarte-grau) on the native LV95 tile grid.

Label overlay: wmts.asit-asso.ch asitvd.fond_pourortho, published on the identical LV95 grid. It sits in its own pane above the data layers.

Dates: the calendar and the ‹ › buttons query the STAC API data.geo.admin.ch/api/stac/v0.9. Cloud cover is CLOUDPERCENTAGE from each mosaic's metadata.json (OmniCloudMask). When several orbits were acquired on the same day, all of them are mosaicked, most recent on top.

Spectral layers: the band COGs are read straight from data.geo.admin.ch over HTTP range requests (geotiff.js). Only the overview matching the zoom and the tiles in view are fetched.

Masks: Clouds hides cloud-mask codes 1 and 2, Cloud shadows code 3, and Terrain shadow terrain-mask value 200 (cast or self-shadow from swissSURFACE3D at acquisition time).

VHI: wms.geo.admin.ch layers ch.swisstopo.swisseo_vhi_v100 and …_vegetation with the item= day selector. Titles and abstracts come from the WMS GetCapabilities document.

Area of interest: the pentagon button on the map draws a rectangle (axis-aligned in LV95) or polygon, or imports KML/KMZ, GPX, WKT, GeoJSON, zipped Shapefiles, an MGRS/GEOREF cell or a bounding box (WGS84, LV95, LV03). Vertices stay editable; drawing again adds a polygon. Statistical info reads the COGs over the area for the selected date (statistics, histogram) and over a date range (time series, CSV); swissEO VHI statistics come from the forest-10m / vegetation-10m COGs. The spectral explorer plots mean reflectance of all 12 bands. The image download can be clipped to the area.

Permalink: the address bar is rewritten on every change (view, date, cloud filter, layer, legend range, masks, effects, compare list, area of interest), so copying the URL reproduces the view.

Projection: EPSG:2056 (CH1903+ / LV95), the native CRS of the tile grid and the COGs, so nothing is reprojected.
